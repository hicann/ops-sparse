# ltmatmul 性能基线采集报告

**算子**: aclsparseLtMatmul (sparse×dense, 2:4 structured sparsity)
**目标芯片**: Ascend 950PR (arch35 / DAV_3510), CANN 9.1.0
**采集日期**: 2026-09-01
**需求来源**: epilogue 功能对齐、原地扩展，无明确性能目标，以基线数据为主

---

## 1. 采集方法学

| 项目 | 说明 |
|------|------|
| **预热** | 每个用例 warmup 迭代（2~5 次，按 problem size 自适应），剔除冷启动开销 |
| **测量** | 多轮采集：每轮 measure 次迭代，共 rounds 轮（自适应：小 shape 20×5=100 样本，大 shape 5×3=15 样本） |
| **计时口径** | aclrtEvent (EventGuard)，仅采集 matmul kernel 执行时间，不含 H2D/D2H/prune/plan 开销 |
| **设备空闲隔离** | 默认 stream，同步执行 (aclrtSynchronizeStream)，无并发干扰 |
| **取值方式** | **稳态中位数**（跨轮 median of per-round medians），不上报单次最优值 |
| **离散度** | 跨轮 stddev + CV (coefficient of variation = stddev/mean)，用于检测波动 |
| **瓶颈分解** | 理论 FLOPs/bytes 占比 + 实测 GFLOPS / GB/s，双重锁定瓶颈维度 |
| **自适应迭代** | 按 m×k×n 大小分档：>100M→2+5×3, >10M→3+10×3, >1M→3+10×5, 其他→5+20×5 |

### 7.1 离散度分布

| CV 范围 | 用例数 | 占比 | 说明 |

| 0.005~0.01 | 5 | 10% | 轻微波动 |
| > 0.01 | 3 | 6% | 有波动（小 shape 冷启动残留） |

### 7.2 跨轮波动用例

| Tag | median(ms) | min(ms) | max(ms) | CV | 原因分析 |
|-----|-----------|---------|---------|-----|----------|
| S-FP32-64x64x64 | 0.2189 | 0.2148 | 0.2295 | 0.0123 | 小 kernel 时间短（0.2ms），事件精度噪声占比大 |

**方差处理结论**: 所有用例 CV < 1.3%，稳态中位数可靠。小 shape 的高 CV（~1%）源于 aclrtEvent 精度限制（~0.01ms），不影响中位数稳定性。大 shape CV < 0.1%，极稳定。

## 8. 关键发现与建议

### 8.1 性能特征

1. **计算主导型算子**: 80% 的用例计算占比 > 90%，matmul kernel 效率良好
2. **INT8 优势明显**: 大 shape 下 INT8 吞吐 284 GFLOPS，与 FP16（294）接近，但计算量减半
3. **epilogue 开销可控**: FP32 bias+ReLU +8%，FP16 +24%；但 INT8 bias+ReLU 开销 +116%（需关注）
4. **batch 线性扩展**: 线性度 0.92~0.94，有轻微摊薄效应
5. **3vec 极限场景瓶颈转移**: m=15744+小 k/n 时，标量数据量与 FLOPs 同量级，瓶颈从计算转为标量+计算混合

### 8.2 优化建议

| 优先级 | 建议 | 预期收益 | 涉及维度 |
|--------|------|----------|----------|
| P1 | INT8 epilogue 路径优化 | bias+ReLU 开销从 +116% 降至 <+30% | 标量/计算 |
| P2 | 大 m + 3vec 标量预取优化 | 标量维度占比从 50% 降至 <20% | 标量(H2D) |
| P3 | 小 shape kernel 启动开销 | 64×64×64 从 0.22ms 降至 <0.15ms | 标量(调度) |

- FP32: 4 字节对齐 → k,n 是 4 的倍数
- FP16/BF16: 2 字节对齐 → k,n 是 8 的倍数
- INT8: 1 字节对齐 + MMA 约束 → k,n 是 32 的倍数
